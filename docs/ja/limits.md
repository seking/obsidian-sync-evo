# 制限

[English](https://github.com/seking/obsidian-sync-evo/blob/main/docs/limits.md)

## まだ対応していないこと

- **サブモジュールの中の変更。** サブモジュールの中身はダウンロードし、読むだけです。[サブモジュール](#サブモジュール)を見てください。
- **Git LFS。** ポインターファイルを、そのまま同期します。ポインターが指す本体は、ダウンロードしません。
- **改行コードの変換。** `.gitattributes` の `text` と `eol` の設定は、効きません。どのファイルも、リポジトリにあるとおりに、1バイトも変えずに保存し、書き込みます。
- **シンボリックリンク。** [シンボリックリンク](#シンボリックリンク)を見てください。
- GitHub・Dropbox・Google Drive 以外の**サービス**。
- **Google Drive での統合。** 2台のデバイスで変えたファイルは、両方を残します。[Google Drive](google-drive.md#github-や-dropbox-との違い)を見てください。
- **38 MB を超えるファイル**と、100,000を超えるファイルのリポジトリ。[大きさ](#大きさ)を見てください。

## 大きさ

- 38 MB を超えるファイルは、同期しません。
- 100,000を超えるファイルのリポジトリは、同期できません。
- ファイルの一覧が 7 MB を超えるリポジトリは、同期できません。

## 下位のフォルダの `.gitignore`

下位のフォルダの `.gitignore` は、通常のファイルとして同期します。規則としては読みません。効くのは、ルートの物だけです。

## シンボリックリンク

- リポジトリのリンクは、デバイスに書き込みません。リポジトリでは、そのままにします。
- 設定画面に、その一覧が出ます。
- パソコンでは、保管庫の中のリンク（Windows ではジャンクションも）は同期せず、その先にある物も同期しません。そこからは何もアップロードしません。ダウンロードでも、そこには何も書き込まず、何も削除しません。リンクが保管庫の外を指していても同じです。
- リンクを最初に見つけた同期で、そのことを知らせます。

## サブモジュール

サブモジュールの中身は、保管庫のリポジトリが指すコミットの物を、そのフォルダにダウンロードします。そのコミットが変わると、ダウンロードし直します。デバイスでは、通常のフォルダです。

**読むだけです。**

- デバイスで、サブモジュールの中のファイルを変えたり、足したり、削除したりしても、アップロードしません。
- その変更はそのデバイスに残り、どのファイルかを Sync Evo が一度知らせます。
- そのような変更は、パソコンの git で行ってください。
- 後でサブモジュールの側で同じファイルが変わると、デバイスの物は `_conflicts/` に競合ファイルとして残ります。統合はしません。

**要ること。**

- サブモジュールが、トークンで読める GitHub のリポジトリを指していること。[トークンの権限](settings.md#トークンの権限)を見てください。
- 保管庫のリポジトリのルートの `.gitmodules` に、載っていること。
- URL は、`https://github.com/owner/name`、`git@github.com:owner/name`、`../name` の形を読めます。

**ダウンロードできない時**は、デバイスのそのフォルダにすでにある物をそのままにし、理由を Sync Evo が一度知らせます。次の時に、こうなります。

- トークンで、そのリポジトリを読めない。
- そのコミットが、まだそこに push されていない。
- ほかのホストを指している。
- サブモジュールの中のサブモジュールである。

除外しているサブモジュール（除外フォルダの中にある物など）は、ダウンロードしません。

## Android

### 大文字と小文字だけを変える名前の変更

Android の Obsidian は、大文字と小文字だけを変える名前の変更（`tools/` を `Tools/` に）を断ります。その時 Sync Evo は、末尾に `.sync-evo-renaming` を付けた名前を挟んで、2回で変えます（`tools` → `Tools.sync-evo-renaming` → `Tools`）。

名前の変更は、これで入ります。ただしフォルダの時は、Obsidian を再起動するまで、古い綴りでもファイル一覧に見えることがあります（`Tools/` の横に `tools/`）。名前を変えた同期の後に、Sync Evo がそれを知らせます。

- 古い綴りの方は、消さないでください。どちらも同じフォルダなので、本物のフォルダが中身ごと消えます。
- Obsidian を再起動すると、古い綴りは見えなくなります。
- アップロードには、影響しません。
- 原因は、Android の Obsidian の側にあります。名前を変えた後も、そのフォルダの中への書き込みを、古い名前でも知らせ続けます。Sync Evo からは防げません。

**2回で変える時のこと。**

- 末尾に `.sync-evo-renaming` が付いた名前は、同期しません。
- 2回の間で同期が止まった時は、次の同期で名前を戻し、名前の変更の続きを行います。
- Sync Evo は2回の間に書き置きを残さないので、自分が付けた名前かどうかは、サービスと前回の同期にある物で見分けます。ファイルは、`.sync-evo-renaming` を除いた名前のファイルがある時に戻します。フォルダは、その名前のフォルダの中にファイルがある時に戻します。入れ子になった名前も、内側まで戻します。
- それ以外の、末尾に `.sync-evo-renaming` が付いた物は、そのままにします。同期せず、知らせもしません。利用者が自分でそう名付けたファイルやフォルダ（フォルダ `Notes/` の横のファイル `Notes.sync-evo-renaming` など）が、これに当たります。2回の間で残った物のうち、まだ同期したことのない物も、サービスからその名前が消えると、これに当たります。
- サービスにある名前の末尾に、利用者が `.sync-evo-renaming` を付けて作ったファイルやフォルダ（サービスに `Notes.md` がある時のファイル `Notes.md.sync-evo-renaming`）は、Sync Evo が付けた物と見分けられず、次の同期でその名前に戻そうとします。
- その間に、ほかの物がその名前を使っていた時は、ファイルやフォルダを `.sync-evo-renaming` の付いた名前のままにし、1回だけ知らせます。戻すまでは、その名前へのダウンロードも、そこでの削除もせず、同期は完了しません。その名前にある物を移すか名前を変えると、次の同期で名前を戻します。
- `.sync-evo-renaming` の付いた名前の間に変えたファイルは、その後、両方が残ることがあります。サービスの物がその名前になり、保管庫の物は `_conflicts/` に競合ファイルとして残ります。

### 1ファイルずつダウンロードする

Android では、いつも1ファイルずつダウンロードします。コミット全体の zip は使いません。Obsidian のリクエストの関数が、大きな応答でメモリが足りなくなるためです。

そのため、約5,000ファイルを超える保管庫の最初のダウンロードは、GitHub の1時間ごとのリクエストの上限にかかります。

- 手動で始めた同期は、上限が解けるのを待つので、1時間以上かかります。
- ひとりでに始まった同期は、そこで止まり、後の同期が続きを進めます。

2 MB 以上のファイルは、WebView の `fetch` でダウンロードします。メモリが足りなくなる部分を通らないためです。

## 試した環境

- iPhone（iOS）と Mac（macOS）。
- 基本の同期は、Android のスマートフォン1台（Pixel 6a）、iPad 1台、Windows 11 のパソコン1台でも試しました。
- Linux では、まだ試していません。
- Dropbox は、Android のスマートフォン1台と iPhone 1台で試しました。パソコンでは、まだです。
- Google Drive は、Android のスマートフォン1台（Pixel 6a）で試しました。iPhone とパソコンでは、まだです。
