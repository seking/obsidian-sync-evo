# 同期のしくみ

[English](https://github.com/seking/obsidian-sync-evo/blob/main/docs/syncing.md)

Sync Evo は、大きな保管庫とスマートフォンのために作りました。

- デバイスに git は要りません。
- GitHub・Dropbox・Google Drive の API と、直接やりとりします。
- 数千ファイルの最初のダウンロードが途中で止まっても、続きから進めます。

同期の相手は、GitHub ではリポジトリ、Dropbox と Google Drive では、そこにある保管庫のフォルダです。違う点は、[Dropbox](dropbox.md) と [Google Drive](google-drive.md) にあります。

## ダウンロード、アップロード、同期

- **ダウンロード**は、保管庫をサービスの物に合わせます。サービスで新しくなったファイルや変わったファイルを受け取り、サービスで削除されたファイルを削除します。
- **アップロード**は、保管庫で足した物、変えた物、削除した物を送ります。GitHub では、1つのコミットになります。
- **同期**は、その両方です。ダウンロードしてから、アップロードします。リボンのボタンも、これです。

## 同期する時

有効にしない限り、ひとりでには何も動きません。同期するのは、ボタンを押した時か、コマンドを実行した時です。

設定の「同期のしかた」で、次の時にも同期させられます。

- Obsidian を起動した時と、ほかのアプリから戻った時。
- 一定の間隔で。Obsidian が前に出ている間だけです。

自動同期は、次のように動きます。

- 変更のアップロードも許さない限り、ダウンロードだけを行います。
- うまくいった時は、何も知らせません。
- [下の確認](#sync-evo-が止まって確かめる時)に、代わりに答えることはありません。その時は何も変えず、手動で同期するよう一度だけ知らせます。
- 保管庫の最初のダウンロードは始めません。それは自分で始めます。
- 入力中のノートは、そのままにします。入力を20秒止めた後の同期で、そのノートを更新するか、アップロードします。
- 自動同期の最中に自分で同期を始めると、そちらに置き換わります。

この設定は、[同期のしかた](settings.md#同期のしかた)にあります。

## 両方で変わったファイル

保管庫とサービスの両方で変わったファイルは、上書きしません。

### 統合

GitHub と Dropbox では、そのようなファイルを、できる時は統合します。Google Drive では統合せず、[競合ファイル](#競合ファイル)として両方を残します。

- ファイルは、元の名前のまま、両方の変更を行単位で受け取ります。
- 同期の知らせに、そのファイルの名前が出ます。
- 統合する前にデバイスにあった内容は、保管庫の `.trash/.sync-evo-merged/` に残します。

その写しの名前は `<date> <name>.<extension>` です。

- `notes/a.md` なら、`.trash/.sync-evo-merged/2026-10-13 a.md` です。
- 同じ日の2つめは、`2026-10-13 a (1).md` です。

`.trash/.sync-evo-merged/` フォルダは、

- 同期しません。
- Obsidian に表示されません。
- Sync Evo が削除することはありません。中身が要らなくなったら、削除してください。

### 統合したファイルの前の内容を戻す

写しを読んだり戻したりするには、デバイスのファイル管理のアプリを使います。写しを、Obsidian に表示される保管庫のフォルダへ移します。

- **Mac**：Finder で `⌘⇧.` を押すと、名前がドットで始まるフォルダが表示されます。
- **Android**：ファイル管理のアプリのメニューで、「隠しファイルを表示」を選びます。
- **iPhone と iPad**：「ファイル」アプリには、これらのフォルダは出ません。検索で、ノートの名前から写しが見つかります。結果を長押しして、「移動」を選びます。

### 競合ファイル

統合せずに、ファイルを両方残すのは、次の時です。

- 両方で同じ行を変えた時。
- テキストでない時。
- `.canvas` か `.base` の時。
- 設定の「同期のしかた」の「競合した時」を、競合ファイルを作る方にしたデバイスでは、いつも。
- Google Drive では、いつも。

その時は、

- サービスの物が、元の名前のまま残ります。
- 保管庫の物は、競合ファイルとして、保管庫のルートの `_conflicts/` フォルダに残ります。
- 同期の知らせに、両方のファイルの名前が出ます。

競合ファイルの名前は `<date> <name> (<device>).<extension>` です。

- `notes/a.md` の競合ファイルは、`_conflicts/2026-10-12 a (iPhone).md` です。
- 同じノートの同じ日の2つめは、`_conflicts/2026-10-12 a (iPhone) (1).md` です。

ほかに、

- 競合ファイルは、何を除外していても、ほかのファイルと同じように同期します。
- 設定フォルダの中のファイルには、競合ファイルを作りません。保管庫の物は、保管庫の `.trash/` に入ります。

### 競合ファイルは30日で片付ける

- 競合ファイルは、名前の日付の日が終わってから30日、残します。
- その後、同期の時に保管庫の `.trash/` へ移し、移した数を知らせます。
- 次のアップロードで、サービスの物を削除します。ほかのデバイスは、ほかの削除されたファイルと同じように、それを消します。
- 競合ファイルを残したい時は、`_conflicts/` の外へ移すか、名前を変えます。

### 0.2.0 以前の競合ファイル

0.2.0 までは、競合ファイルを元のファイルの隣に、`<name>.conflict-from-<device>-<date>-<time>.<extension>` という名前で作っていました。この形の競合ファイルは、

- そのままの場所に残ります。
- これまでどおり同期します。
- `.trash/` へ移すことはありません。

## Sync Evo が止まって確かめる時

Sync Evo は、次の時に止まり、確かめてから進めます。

- ダウンロードやアップロードで、多くのファイルを削除する時。50より多いか、5より多く、しかも全ファイルの10分の1より多い時です。
- アップロードで、前に同期したファイルが保管庫に1つも見つからない時。数がどれだけ少なくても確かめます。保管庫のフォルダを消して作り直すと、こうなります。この時 Sync Evo は、サービスで削除する代わりに、サービスからダウンロードし直すことができます。
- 最初のダウンロードで、保管庫にサービスの物と違うファイルがある時。
- デバイスが初めてアップロードする時。
- リポジトリの履歴が書き換えられた時（force push）。

## コマンド

| コマンド | すること |
| --- | --- |
| 同期する | ダウンロードしてから、アップロードします。 |
| GitHub（または Dropbox、Google Drive）から変更をダウンロードする | サービスからダウンロードするだけです。 |
| GitHub（または Dropbox、Google Drive）へ変更をアップロードする | サービスへアップロードするだけです。 |
| 最初からやり直す（GitHub、Dropbox、Google Drive から全部ダウンロードし直す） | 最初のダウンロードと同じように、保管庫とサービスを比べ直します。ファイルは削除しません。 |
| 同期を中止する | 実行中の同期を止めます。 |
| 同期ログを表示 | Sync Evo が読み込まれてからしたことを示します。**すべてコピー**で、バグの報告に写せます。 |
| 前回の同期の結果を表示 | 知らせることがあった最近の同期を、全部のファイルと一緒に示します。 |

アップロード：

- このデバイスが最後にダウンロードした後に、サービスで変わったファイルは、上書きしません。次のダウンロードに残します。
- デバイスは、最初のアップロードの前に、一度ダウンロードする必要があります。

同期を中止する：

- 中止したダウンロードは、続きから進みます。
- 中止したアップロードは、ブランチを変えません。それまでにアップロードした物は、どのコミットにも入りません。
- Google Drive では、中止したアップロードがそれまでに送ったファイルは、そこに残ります。次の同期で、残りを送ります。
- Dropbox では、アップロードの最後に、ファイルをまとめて確定します。残るのは、確定済みの物だけです。それより前に中止すると、Dropbox には何も残りません。次の同期で、残りを送ります。

GitHub では、アップロードで1つのコミットを作ります。コミットメッセージは `Sync Evo: <device name> (<n> added, <n> modified, <n> deleted)` で、その下に変わったパスが並びます。
